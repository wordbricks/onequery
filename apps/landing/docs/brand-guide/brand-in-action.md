# Brand In Action

This guide explains how OneQuery's brand system should appear across real
surfaces: website, docs, README, blog, social images, presentations, videos, and
product launch materials.

## Website

The website should behave like product proof, not a campaign page.

Use:

- White-first canvas
- Near-black type
- Compact OneQuery mark
- Product UI frames as the main visuals
- Short sections with one claim each
- Real workflow states

Avoid:

- Oversized decorative hero art
- Gradient backgrounds
- Abstract AI visuals
- Long narrative blocks
- Floating card-heavy section layouts

## Documentation

Docs should be practical and exact.

Use:

- Clear page titles
- Short intros
- Commands in code blocks
- Concrete examples
- State-based troubleshooting
- Links to source files when relevant

Avoid:

- Marketing claims in setup instructions
- Vague troubleshooting
- Screenshots without captions
- Future product promises

## README

The README should answer:

1. What is OneQuery?
2. Who is it for?
3. What can I do now?
4. How do I install it?
5. What sources and surfaces are supported?
6. Where are credentials and audit records handled?

Keep the README developer-first. Use badges only for factual status.

## Blog

Blog visuals and writing should connect technical ideas to controlled workflows.
For newly supported data sources, use the repeatable thumbnail pattern in
`data-source-blog-thumbnails.md`.

Good blog themes:

- Safe agent access to production data
- Query validation and audit history
- Connector architecture
- Self-hosting and credential boundaries
- Cost limits and operational guardrails

Avoid:

- Generic AI thought leadership
- Stock-like data visuals
- Warm editorial illustration styles
- Claims about capabilities that are not current

## Social Images

Social images should be readable at small sizes.

Use:

- One large, literal headline
- One product frame or diagram
- Small OneQuery mark
- White or near-white background
- Minimal supporting copy

Avoid:

- Dense screenshots
- Tiny code blocks
- Decorative logo patterns
- Gradient backgrounds
- Multiple competing visual ideas

## Presentations

Presentation slides should look like infrastructure documentation with better
spacing.

Use:

- One idea per slide
- Large `Geist` headings
- Product UI or diagram proof
- Minimal bullets
- Consistent white canvas

Avoid:

- Dense wall-of-text slides
- Decorative section dividers
- Partner logo clouds as primary proof
- AI sparkle visuals

## Video And Motion

Motion should show workflow progress.

Good sequences:

- Source connected
- Agent request received
- Query validated
- Connector job dispatched
- Result returned
- Audit record created

Avoid:

- Decorative motion loops
- Fast animated backgrounds
- Magic-style AI reveals
- Motion that hides product state

## Launch Assets

For launches, lead with the concrete capability:

Good:

> Agent query access with source policies and audit history.

> Self-host OneQuery and run read-only queries from the CLI.

Avoid:

> The future of AI data work is here.

> Meet your new data brain.

## Surface Checklist

Before publishing a brand asset:

- The primary audience is developers.
- Agent-ready claims are bounded and current.
- The OneQuery mark appears intentionally, not repeatedly.
- The page stays monochrome-first.
- Product UI, diagram, or code provides proof.
- Claims do not exceed current documented capability.
- Accessibility basics are covered.
